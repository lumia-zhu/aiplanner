# 🎯 Agent 建议工具设计方案

## 一、功能定位

### 1.1 核心目标
为用户提供**个性化、可执行的任务建议**，帮助用户：
- 完善模糊或不完整的任务
- 制定合理的执行计划
- 发现潜在问题并提前规避
- 提升整体任务管理效率

### 1.2 与现有工具的区别

| 工具 | 功能 | 输出 |
|------|------|------|
| `get_tasks` | 查询任务列表 | 任务数据 |
| `analyze_tasks` | 分析任务问题 | 问题诊断 |
| **`suggest`（新）** | 给出行动建议 | **可执行的建议** |

**关键差异**：
- `analyze_tasks` 告诉你"有什么问题"
- `suggest` 告诉你"应该怎么做"

## 二、使用场景

### 场景 1：单任务完善建议
**用户输入**：
> "帮我完善一下'写论文'这个任务"

**AI 建议输出**：
```
📝 任务完善建议：写论文

1. 🎯 任务拆解建议
   - 确定论文主题和大纲（预估 2h）
   - 收集参考文献（预估 3h）
   - 撰写初稿（预估 8h）
   - 修改润色（预估 4h）

2. ⏰ 时间安排建议
   - 建议截止日期：12月15日（距今20天）
   - 每天投入：2-3小时
   - 最佳工作时段：上午9-11点（根据你的习惯）

3. ⚠️ 风险提示
   - 你下周有3个其他高优先级任务，建议本周多推进
   - 周末可能是集中写作的好时机

4. 💡 执行技巧
   - 先完成大纲，再填充内容
   - 使用番茄工作法保持专注
```

### 场景 2：多任务优先级建议
**用户输入**：
> "我这周任务太多了，帮我排一下优先级"

**AI 建议输出**：
```
📊 本周任务优先级建议

🔴 紧急重要（立即处理）
1. 提交项目报告 - 截止明天
2. 回复导师邮件 - 已逾期1天

🟡 重要不紧急（安排时间）
3. 准备周五演讲 - 建议周三完成
4. 复习考试内容 - 每天1小时

🟢 可延后
5. 整理笔记 - 可放到周末
6. 学习新技能 - 建议下周开始

💡 执行建议：
- 今天优先处理第1、2项
- 明天开始准备演讲
- 利用碎片时间复习
```

## 三、技术设计

### 3.1 工具参数设计

```typescript
interface SuggestToolParams {
  userId: string
  
  // 建议类型
  suggestionType: 'task_improvement' | 'priority' | 'schedule' | 'general'
  
  // 目标范围
  scope: {
    type: 'single_task' | 'multiple_tasks' | 'date_range' | 'all'
    taskIds?: string[]           // 指定任务ID
    dateRange?: {                // 日期范围
      start: string
      end: string
    }
  }
  
  // 可选：用户额外说明
  userContext?: string
}
```

### 3.2 建议类型说明

| 类型 | 说明 | 典型触发词 |
|------|------|------------|
| `task_improvement` | 完善单个任务 | "完善"、"优化"、"改进" |
| `priority` | 优先级排序建议 | "排优先级"、"先做哪个" |
| `schedule` | 时间安排建议 | "规划"、"安排"、"计划" |
| `general` | 综合建议 | "有什么建议"、"怎么做比较好" |

### 3.3 数据输入

工具执行时需要收集以下信息：

```
┌─────────────────────────────────────────────────┐
│                  输入数据                        │
├─────────────────────────────────────────────────┤
│  1. 用户个人信息（UserProfile）                  │
│     - 身份/职业                                  │
│     - 工作习惯（早起/夜猫子）                    │
│     - 每日可用时间                              │
│     - 个人目标                                  │
│                                                 │
│  2. 任务数据                                    │
│     - 目标任务详情                              │
│     - 相关任务上下文                            │
│     - 历史完成情况                              │
│                                                 │
│  3. 时间上下文                                  │
│     - 当前日期/时间                             │
│     - 近期日程安排                              │
│     - 截止日期分布                              │
└─────────────────────────────────────────────────┘
```

### 3.4 输出格式

```typescript
interface SuggestionResult {
  type: 'success' | 'error'
  data?: {
    suggestionType: string
    title: string
    
    // 主要建议内容
    suggestions: Array<{
      category: string      // 建议分类
      icon: string          // 显示图标
      title: string         // 建议标题
      description: string   // 详细说明
      priority: 'high' | 'medium' | 'low'
      actionable: boolean   // 是否可直接执行
      action?: {            // 可执行动作
        type: 'create_task' | 'update_task' | 'set_deadline' | 'decompose'
        params: any
      }
    }>
    
    // 风险提示
    risks?: Array<{
      level: 'warning' | 'danger'
      message: string
    }>
    
    // 执行技巧
    tips?: string[]
    
    // 参考依据
    reasoning: string
  }
  message?: string
}
```

## 四、Prompt 设计要点

### 4.1 系统提示词结构

```
你是一个任务管理专家，需要根据用户的个人情况和任务数据，给出实用的建议。

【用户画像】
{userProfile}

【当前任务情况】
{taskContext}

【建议要求】
1. 建议必须具体、可执行
2. 考虑用户的时间和精力限制
3. 识别潜在风险并提前预警
4. 建议应该循序渐进，不要过于激进

【输出格式】
...
```

### 4.2 个性化考量因素

1. **时间维度**
   - 用户每天可用时间
   - 最佳工作时段
   - 周末是否可用

2. **能力维度**
   - 任务历史完成率
   - 平均完成时间
   - 擅长/不擅长的任务类型

3. **压力维度**
   - 当前任务负载
   - 近期截止日期密度
   - 是否有紧急任务

### 5.2 交互流程

```
用户请求建议
     ↓
AI 收集上下文
     ↓
生成个性化建议
     ↓
展示建议卡片
     ↓
用户选择操作
     ├─→ [应用建议] → 自动执行建议中的动作
     ├─→ [修改后应用] → 用户调整后执行
     └─→ [忽略] → 关闭卡片
```

## 八、注意事项

### 8.1 避免过度建议
- 用户只问简单问题时，不要给出长篇大论
- 建议数量控制在 3-5 条以内
- 优先给出最重要的建议

### 8.2 保持建议可执行性
- 每条建议都应该是具体的行动
- 避免空泛的"努力"、"加油"类建议
- 提供明确的时间、数量等指标

### 8.3 尊重用户自主权
- 建议是"建议"，不是"命令"
- 提供多个选项让用户选择
- 允许用户忽略或修改建议

### 示例 1：完善任务

```
👤 用户：帮我完善一下"准备面试"这个任务

🤖 AI：
好的，我来帮你完善"准备面试"这个任务。

📝 **任务完善建议**

**1. 任务拆解**
建议将"准备面试"拆分为以下子任务：
- [ ] 研究目标公司背景（1h）
- [ ] 复习技术知识点（4h）
- [ ] 准备自我介绍（1h）
- [ ] 模拟面试练习（2h）
- [ ] 准备要问面试官的问题（0.5h）

**2. 时间建议**
- 总预估时间：8.5小时
- 建议在面试前3天开始准备
- 每天投入2-3小时

**3. 优先级建议**
- 设为"高优先级"
- 如果面试时间紧迫，优先复习技术知识

需要我帮你创建这些子任务吗？
```
